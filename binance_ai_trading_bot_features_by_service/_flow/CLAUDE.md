## What this system does

An automated crypto trading bot for Binance with three operating modes:

- **Backtest** — replay historical candles against a strategy
- **Paper** — execute on Binance testnet (no real money)
- **Live** — execute on Binance mainnet (real money, gated by explicit confirmation)

Trading signals come from rule-based strategies (RSI, EMA, MA crossover, volume) and/or an AI model. A risk engine sits between signal and execution; nothing reaches the order manager without passing risk checks.

## Architecture (3 services, 1 monorepo)

```
[Frontend (React/Vite/TS)] ──HTTPS/WS──> [Backend (Go)] ──gRPC/HTTP──> [AI Service (Python)]
                                              │
                                              └──REST/WS──> [Binance]
```

- **Frontend** — operator UI: dashboard, bot control, market watch, backtest results, alerts
- **Backend (Go)** — owns market data, strategy execution, risk, orders, paper/backtest engines, alerts, auth, API gateway. Stateful runtime.
- **AI Service (Python)** — owns datasets, feature engineering, training, model registry, inference. Stateless inference API.

The Go backend is the **only** service that talks to Binance. Frontend and AI never call Binance directly.

## Risk policy (cross-cutting — enforce in code, not just docs)

These rules apply to **every** mode (backtest, paper, live). Violations must `error`, not `warn`.

1. **Position sizing** — no single position exceeds `risk.max_position_pct` of equity (default 2%)
2. **Daily drawdown** — bot halts itself if realized + unrealized loss exceeds `risk.max_daily_drawdown_pct` (default 5%)
3. **Stop loss required** — every order submitted must have an associated stop loss price; the order manager rejects orders without one
4. **Slippage check** — market orders compute expected slippage from order book depth; if estimated slippage > `risk.max_slippage_bps` (default 30 bps), order is rejected
5. **Live trading gate** — switching to live mode requires (a) explicit user confirmation in UI, (b) `LIVE_TRADING_ENABLED=true` env var, (c) successful API key permission validation. Missing any one → reject.
6. **Kill switch** — a single `POST /api/bot/kill` cancels all open orders, flattens positions, and disables further entries until manually re-enabled

## Conventions that span all services

- **Time** — always UTC, always `int64` Unix milliseconds in transport. Convert to local only at the UI edge.
- **Money** — never `float64`. Go uses `decimal.Decimal` (`shopspring/decimal`); Python uses `Decimal`; transport as string ("0.00012345").
- **IDs** — ULIDs, lowercase, generated by the producer
- **Logging** — structured. Required keys on every log line: `service`, `mode` (backtest|paper|live), `symbol` (when applicable), `request_id`
- **Errors** — never swallow. Either return up the stack or log at `error` level with full context.
- **Config** — YAML files in `config/`, validated on startup. Environment variables override file values. Never hardcode symbols, thresholds, or API keys.
